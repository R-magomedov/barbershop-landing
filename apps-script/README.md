# Google Apps Script: установка и перенос

Code.gs — полная серверная версия. CAPTCHA удалена; Cloudflare и его ключи больше не нужны.

## Установка обновления

1. Сохраните копию текущего кода в редакторе Apps Script.
2. Целиком замените содержимое Код.gs файлом apps-script/Code.gs. Не добавляйте в конец.
3. Оставьте часовой пояс Europe/Moscow и свойство CALENDAR_ID с ID тестового календаря. Существующие BOOKING_<requestId> и PUBLIC_BOOKING_RATE сохраняйте: это история повторов и лимитов.
4. Сохраните проект. Управление развертываниями → карандаш → новая версия → развернуть. Выполнение от имени владельца, доступ для всех. URL /exec остаётся прежним.
5. После серверного обновления опубликуйте клиент. Для сборки нужен только VITE_APPS_SCRIPT_URL. Старые TURNSTILE_SECRET_KEY, BOOKING_ALLOWED_HOSTNAMES, BOOKING_TEST_TOKEN и VITE_TURNSTILE_SITE_KEY не используются; их можно удалить из настроек.

Один деплой Vercel не обновляет Apps Script. Старый сервер продолжит отклонять заявки без токена до выполнения шага 4.

## Как работает запись

- GET action=slots возвращает только свободные часы без контактов и названий событий.
- POST action=book принимает serviceId, name, phone, date, time, requestId и пустое website (скрытая ловушка для простых ботов). Токен CAPTCHA не требуется.
- Сервер проверяет данные и лимиты: 5 новых попыток в минуту, 30 в день на сайт, 2 в день на телефон. Лимиты расходуются до проверки занятости; отклонённый конфликт также считается попыткой.
- Затем createBooking под ScriptLock повторно проверяет занятость и создаёт событие. Блокировка синхронизирует только этот скрипт, а не ручное редактирование календаря.
- Известный requestId сверяет отпечаток полей и возвращает прежнее подтверждение без расхода лимитов и создания дубля, в том числе после начала записи. Изменённые поля с прежним ID запрещены.
- Неопределённая прежняя попытка без найденного события не создаётся заново: её проверяет мастер.
- BOOKING_* хранятся 120 дней. Уборка при новых валидных запросах также удаляет оставшиеся TURNSTILE_USED_* старше 10 минут, сохраняя прочие настройки.

Это базовая защита учебного проекта. Без CAPTCHA автоматические заявки могут расходовать лимиты и занимать часы; для реального бизнеса защиту следует пересмотреть по нагрузке.

Успех: {ok:true,replayed:false,booking:{eventId,requestId,date,time,serviceId,timeZone}}. Повтор: replayed=true. Ошибка: {ok:false,code,error}. Контактов в ответе нет. Клиент очищает поля только после проверки подтверждения своей заявки.

## Копия для другого барбершопа

Создайте отдельные репозиторий, проект Vercel, Google Календарь и Apps Script. Копируйте исходники без .git, .vercel, .env, node_modules, dist и чужих ключей. Задайте свой CALENDAR_ID и Web App URL.

Обновите контакты, цены, карту и оформление. ID и длительности услуг меняются согласованно в BOOKING_CONFIG и src/bookingSchedule.js. Расчёты используют московское время и +03:00.

## Проверки

npm run test проверяет серверный контракт и клиентский POST с подставными сервисами без сетевых записей. npm run build проверяет сборку. Полный путь нужно проверить после публикации обновлённых Apps Script и клиента в тестовом календаре.


## Обновление списка услуг

В форму добавлены все шесть услуг прайса, чистка лица удалена. Длительности: мужская стрижка — 60 мин, борода / окантовка — 30, камуфляж бороды — 30, камуфляж головы — 40, комплекс — 90, детская стрижка — 60. Для новых услуг замените Code.gs и опубликуйте новую версию существующего развертывания по инструкции выше. Старый edging оставлен на сервере для прежних заявок, отдельного пункта в форме нет.
