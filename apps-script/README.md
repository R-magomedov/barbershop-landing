# Google Apps Script: установка и перенос

`Code.gs` — полная актуальная версия серверного кода. Секретов в файле нет. Этот код не запускается Vite и не попадает во фронтенд.

## Установка текущего обновления

1. Сохраните копию текущего кода в редакторе Apps Script для истории.
2. Замените всё содержимое вашего `Код.gs` содержимым `apps-script/Code.gs`. Не добавляйте его в конец: иначе появятся повторные определения doGet/doPost и других функций. Старые учебные test*-функции в эту версию не включены.
3. В настройках Apps Script оставьте часовой пояс Europe/Moscow. Проверьте свойства:

| Свойство | Содержимое |
| --- | --- |
| CALENDAR_ID | ID календаря «Барбершоп — тест» |
| TURNSTILE_SECRET_KEY | Рабочий Secret key из Cloudflare, только здесь |
| BOOKING_ALLOWED_HOSTNAMES | barbershop-ru.vercel.app; при нескольких сайтах — список через запятую |

4. Сохраните проект. Обновите существующее развертывание: управление развертываниями → карандаш → новая версия → развернуть. Выполнение от имени владельца, доступ для всех. URL /exec остаётся прежним.
5. Если Google запросит разрешение на внешние запросы, предоставьте его своему скрипту: Siteverify проверяет одноразовый токен на стороне Google, через UrlFetchApp.
6. Сайт должен быть собран с VITE_APPS_SCRIPT_URL и VITE_TURNSTILE_SITE_KEY. Site key публичный; Secret key и BOOKING_TEST_TOKEN во фронтенд не передавайте.

Старый BOOKING_TEST_TOKEN новой публичной doPost не используется. CALENDAR_ID и существующие BOOKING_<requestId> сохраняйте: по ним распознаются повторы уже созданных заявок. Проект остаётся на Vercel, перенос домена в Cloudflare не нужен.

## Как работает запись

- GET action=slots получает часы. Возвращаются только времена, без названий событий и контактов.
- POST action=book принимает serviceId, name, phone, date, time, requestId, turnstileToken и пустое website (ловушка для ботов).
- Новая заявка проходит серверную валидацию, Siteverify с проверкой hostname/action=booking и лимиты. Затем createBooking под ScriptLock ещё раз проверяет занятость и создаёт событие.
- Повтор известного requestId сверяет отпечаток данных и возвращает/восстанавливает прежний результат. Изменённые данные с прежним ID запрещены. Даже если начало записи уже наступило, известная заявка может получить подтверждение.
- Неопределённая попытка без найденного события автоматически не создаётся заново. Нужна проверка мастера, чтобы не получить дубль.
- Токен дополнительно связан с requestId в собственном хранилище: проверка повторного использования на стороне Cloudflare может быть не мгновенной.
- Значения по умолчанию: 5 новых проверенных попыток в минуту на сайт, 30 в день на сайт, 2 в день на телефон. Повторы известной заявки лимиты повторно не расходуют. Изменяйте числа в BOOKING_CONFIG под реальную нагрузку.
- Записи BOOKING_* хранятся 120 дней; использованные токены — 10 минут. Уборка запускается при новых прошедших Turnstile запросах. Не удаляет CALENDAR_ID, ключи и посторонние настройки. Лимиты и CAPTCHA снижают злоупотребления, но не гарантируют защиту от всех ручных/распределённых атак.
- ScriptLock синхронизирует только этот Apps Script, а не ручное редактирование Google Календаря или другой скрипт.

Успех: `{ok:true,replayed:false,booking:{eventId,requestId,date,time,serviceId,timeZone}}`. Повтор: replayed=true. Ошибка: `{ok:false,code,error}`. Контактов в ответе нет. При ошибке записи не сообщайте пользователю, что заявка отправлена.

## Копия для другого барбершопа

Создайте отдельные репозиторий, проект Vercel, Google Календарь и Apps Script в аккаунте владельца. Копируйте исходники без .git, .vercel, .env, node_modules, dist и ключей. Задайте новые свойства скрипта, Web App URL и Turnstile-виджет для нового сайта.

Обновите контакты, услуги, цены, карту и оформление. ID/длительности услуг согласованно меняются в BOOKING_CONFIG и src/bookingSchedule.js. Эта версия рассчитана на московское время: другие часовые пояса потребуют отдельного изменения разбора времени с +03:00, а не только смены названия зоны.

## Проверки

`npm run test` из корня проекта проверяет логику с подставными Google-сервисами, без сетевых записей. `npm run build` проверяет клиент. Для автоматических браузерных тестов используйте официальные dummy sitekeys на отдельном локальном стенде; тестовые секреты серверная production-версия отклоняет. Полная сквозная проверка требует опубликованного нового Apps Script и корректной пары реальных Cloudflare-ключей.
